Extraction throughput runbook (SM-6)

Symptom: an ingest completes with full-text papers acquired (pdf_ok > 0) but zero entities extracted, and the logs show OpenAI 429 rate_limit_exceeded on the extractor calls.

Why it happens: each paper runs five extractors (problem, topic, concept, model, method) concurrently, and each sends the full paper text to OpenAI. A 50–100k-token paper × 5 calls bursts past the account’s tokens-per-minute (TPM) ceiling. The model tier sets the account’s TPM ceiling; a low-tier model is far too slow to absorb even a single full paper across five extractors.

The two levers

Knob Env var Default What it does
Model / tier LLM_MODEL gpt-6.2-sol The real throughput lever. LLM_MODEL is the one model surface (OPENAI_EXTRACTION_MODEL is a legacy alias).
TPM budget OPENAI_TPM 30000 The proactive throttle’s budget. Set it to match your account’s ceiling for the chosen model so the throttle paces calls correctly.
Completion budget LLM_MAX_OUTPUT_TOKENS 16384 Reasoning + visible output per chat call. Reasoning tokens count against the same ceiling, so an output-sized value truncates a reasoning call. Ranking is batched, so no single response needs the model’s full window.
TPM reservation OPENAI_TPM_RESERVE_TOKENS 4096 Completion tokens the throttle reserves before a call. The completion budget is a truncation ceiling, not a forecast; reserving all of it would pace every call at 16k; 4096 matches the historical output-sized reservation. Actual provider-reported usage above this reserve is charged after the call.

The throttle is a correctness safety-net, not a throughput fix: it stops concurrent calls from all 429-ing, but at a low TPM tier it can only do so by waiting minutes per paper. Raising the model/tier is what makes entities actually flow; the throttle then keeps that larger budget from being blown by concurrency.

Fix: raise the throughput

Set both the model and a matching TPM budget for that tier, then re-run the ingest and confirm entities land. Terraform owns the deployed env now: change llm_model in infra/envs/staging.tfvars (or prod) and apply. For a one-off execution, overlay both values on the Job:

Cloud Run Job (staging / production)

gcloud run jobs execute agentic-kg-ingest-staging \
  --project vt-gcp-00042 --region us-central1 \
  --update-env-vars LLM_MODEL=gpt-6-luna,OPENAI_TPM=450000 --wait

Local / smoke

export LLM_MODEL=gpt-6-luna
export OPENAI_TPM=450000
make smoke-local        # or: agentic-kg ingest --query "..." --limit 3 --json

Verify

The run should now report entities > 0. Check the ingest summary counters (topics_linked, concepts_v2_linked, models_linked, methods_linked) or query Neo4j directly:

MATCH (p:Paper)-[r:BELONGS_TO|DISCUSSES|USES_MODEL|APPLIES_METHOD]->()
RETURN type(r) AS edge, count(*) AS n ORDER BY n DESC

If a run is legitimately throttling, you will see an up-front log line before it blocks — e.g. TPM throttle: ~480s wait for ~250000 tokens (budget 30000 TPM) — which both confirms the stall is the throttle (not a hang) and names the remedy.

Notes

  • The deployed default comes from Terraform (llm_model, currently gpt-6.2-sol); a per-run override is an operator action, not a code change.
  • CI’s smoke-ingest workflow sets LLM_MODEL=gpt-6-luna + OPENAI_TPM=30000 so the Ingest + Assert job proves entities flow under the real ceiling.
  • agentic-kg llm-check makes one tiny real call per configured model, then a bounded ranking-batch probe that mirrors the largest real structured call, and exits non-zero with the provider’s message (including a truncation at the configured completion budget); deploy-master runs it after a deploy and the nightly Job runs it before ingest.
  • Match OPENAI_TPM to your account’s actual tier for the chosen model. Setting it higher than your real ceiling defeats the throttle and reintroduces 429s; setting it lower just paces more conservatively (safe, but slower).
