SEG-12
—
Semantic (LLM/embedding) heading classification instead of enumerated names
Needs Decision — after SEG-7
—
Raised 2026-09-08. The pattern table enumerates section names, and publishers/authors name sections arbitrarily, so the vocabulary can never be complete. Proposal: match similar heading names semantically rather than by enumeration. Measured against the 42 hand-labelled headings in scripts/segment_ground_truth.py (which is a ready-made eval set): current patterns get 27/42 = 64%. The 15 misses are 6 abstract conventions (SEG-3) + 1 no-label (SEG-4) + 2 journal vocabulary (SEG-4) + 3 over-strict anchors (SEG-5d) + 1 descriptive sentence + 2 named after the contribution (III. SciCheck, The Computer Science Knowledge Graph). SEG-3+SEG-4 alone take this to 86%, relaxed anchors to 93%. So the measured marginal value of name-similarity here is 1–4 headings — and the 2 hardest are proper nouns that no name-based method can classify, LLM or embedding. The real unlock is classifying with context (position, sibling headings, first paragraph), which patterns structurally cannot do. Why this waits for SEG-7: the only reason inclusion precision matters is the four-section keep-list. Exclusion vocabulary (references/acknowledgments/appendix) is already 8/8 = 100% accurate with today’s patterns vs 64% for inclusion, so inverting the filter (SEG-7 option 3) largely dissolves this problem with no new machinery. SEG-4 also found the perverse incentive: mapping Data Records→methods gains 6,138 chars purely by mislabelling, because the keep-list rewards it. Hard prerequisites if built: (1) SEG-11 first — unmatched candidate lines run 31–278/paper, 90% author names and table cells, so LLM-classifying them would mint phantom sections with model confidence attached; (2) determinism — Paper.taxonomy_hash + the AC-21 skip-check assume idempotent re-ingestion, so classifications must be cached/persisted (E-7 persists normalization_audit on the Paper node as precedent). Shape if approved: patterns first, LLM fallback for the residue only, following cross_entity_normalizer (closed-set Pydantic Literal, self-validation gates, confidence threshold, audit trail); L-1 is the cost lever. Cost is not the objection — one call per paper covering its whole heading list is trivial beside the 5–6 extraction calls already made. Counter-argument that stands regardless: at D-1 scale (thousands of papers, arbitrary publishers) enumeration does not generalise, and 8 papers understates the problem. Likely the right destination, not the current bottleneck.
